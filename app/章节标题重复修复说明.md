# 正文章节名显示重复问题 - 修复说明

## 问题描述

阅读器中显示章节内容时，章节标题会重复显示两次，影响阅读体验。

**现象**：
```
第一章 开篇
第一章 开篇

正文内容开始...
```

## 问题原因

### 根本原因

在 `ReadActivity.java` 中，章节内容的存储和渲染逻辑存在重复添加标题的问题：

1. **存储阶段**：将 `title + "\n\n" + content` 存入 `chapterContents`
2. **渲染阶段**：调用 `renderChapterContent(chapterIndex, title, content)` 时再次传入title
3. **HTML处理**：`reader.html` 的 `paginate()` 函数根据title参数再次添加标题

**结果**：标题被添加了两次

### 代码流程分析

#### 修复前的错误流程：

```java
// 1. 存储章节内容（ReadActivity.java 第424行、462行、1174行）
chapterContents.set(chapterIndex, title + "\n\n" + content);
// 此时 chapterContents[0] = "第一章\n\n正文内容..."

// 2. 渲染章节（ReadActivity.java 第466行）
renderChapterContent(chapterIndex, title, content);
// 传入: title="第一章", content="第一章\n\n正文内容..."

// 3. JavaScript处理（reader.html）
function loadContent(chapterIndex, title, content) {
    chapterTitle = title;  // "第一章"
    currentContent = content;  // "第一章\n\n正文内容..."
    paginate(content, title);  // 再次添加标题
}

// 4. 分页处理（reader.html 第80-103行）
if (title) {
    // 添加标题到页面
    currentPageLines.push({text: title, ...});  // 再次添加"第一章"
}
// 处理正文时会包含content中的标题
```

**最终显示**：
```
第一章          ← reader.html添加的标题
第一章          ← content中已包含的标题

正文内容...
```

## 修复方案

### 核心思路

**分离标题和内容的存储**：
- `chapterContents` 只存储纯正文内容（不包含标题）
- 标题单独存储在 `chapterList` 中
- 渲染时由 `reader.html` 统一添加标题

### 具体修改

#### 1. 修复本地书籍缓存加载（第424行）

**修改前**：
```java
String title = sp.getString("chapter_title_" + i + "_" + chapterIndex, "第" + (chapterIndex + 1) + "章");
String content = sp.getString("chapter_content_" + i + "_" + chapterIndex, "");
if (!content.isEmpty()) {
    chapterList.get(chapterIndex).setTitle(title);
    chapterContents.set(chapterIndex, title + "\n\n" + content);  // ❌ 重复添加标题
}
```

**修改后**：
```java
String title = sp.getString("chapter_title_" + i + "_" + chapterIndex, "第" + (chapterIndex + 1) + "章");
String content = sp.getString("chapter_content_" + i + "_" + chapterIndex, "");
if (!content.isEmpty()) {
    chapterList.get(chapterIndex).setTitle(title);
    // ✅ 修正：只存储纯内容，不添加标题，避免重复显示
    chapterContents.set(chapterIndex, content);
}
```

#### 2. 修复网络章节内容加载（第462-464行）

**修改前**：

## 数据流对比

### 修复前：
```
SharedPreferences/Network
    ↓
title + "\n\n" + content  ← 添加标题
    ↓
chapterContents[index]
    ↓
renderChapterContent(index, title, content_with_title)
    ↓
loadContent(index, title, content_with_title)
    ↓
paginate(content_with_title, title)  ← 再次添加标题
    ↓
显示：标题 + 标题 + 正文  ❌
```

### 修复后：
```
SharedPreferences/Network
    ↓
content  ← 纯内容
    ↓
chapterContents[index]
    ↓
renderChapterContent(index, title, content)
    ↓
loadContent(index, title, content)
    ↓
paginate(content, title)  ← 只添加一次标题
    ↓
显示：标题 + 正文  ✅
```

## 注意事项

1. **向后兼容**：
   - 已缓存的内容不受影响
   - 新加载的章节使用新逻辑
   - 建议清除旧缓存以避免混合显示

2. **缓存清理**：
   - 如果用户之前已经缓存了包含标题的内容
   - 可能需要重新下载章节以应用修复
   - 或者手动清除章节缓存

3. **性能影响**：
   - 无性能影响
   - 反而略微减少内存占用（少存储标题文本）

4. **其他功能**：
   - 书签功能不受影响（使用chapterList.getTitle()）
   - 阅读进度记录不受影响
   - 搜索功能不受影响

## 后续优化建议

1. **统一内容格式**：
   - 确保所有来源的内容都不包含标题
   - 在LocalBookParser中也遵循此规范

2. **缓存策略优化**：
   - 分别缓存标题和内容
   - 便于独立更新和管理

3. **内容预处理**：
   - 在存储前清理内容中的标题
   - 避免历史数据问题

4. **调试工具**：
   - 添加日志输出章节内容和标题
   - 便于排查类似问题
