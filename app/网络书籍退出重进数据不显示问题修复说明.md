# 网络书籍退出重进数据不显示问题 - 修复说明

## 问题描述

网络书籍阅读后退出重进会不显示数据，此时翻页会提示"正在加载下一章"，再次点击会进入下一章并显示数据。

**现象**：
1. 阅读网络书籍的某一章
2. 退出阅读器
3. 重新进入同一章节
4. **页面空白或只显示标题** ❌
5. 点击翻页 → 提示"正在加载下一章"
6. 再次点击 → 进入下一章并正常显示 ✅

## 问题根源分析

### 原始代码流程

```
退出重进网络书
  ↓
loadChaptersFromServer()
  ↓
loadNearbyCachedChapters(bookId, targetChapter, 15)
  → 从缓存加载周围15章的元数据
  → chapterContents.add(title + "\n\n" + (content != null ? content : "加载中..."))
  → ❌ 问题1: 添加了标题（与之前的修复冲突）
  → ❌ 问题2: 如果缓存中没有内容，添加"标题\n\n加载中..."
  ↓
restoreFromLocalCacheImmediately(targetChapter)
  → 找到阅读记录
  → content = chapterContents.get(chapterIndex)
  → content = "第5章\n\n加载中..."  ← 包含标题和占位符
  ↓
renderChapterContent(chapterIndex, title, content)
  → 传入 title = "第5章"
  → 传入 content = "第5章\n\n加载中..."  ← 已经包含标题！
  ↓
reader.html 的 paginate(text, title)
  → 再次添加标题
  → ❌ 结果：标题显示两次
  ↓
检查是否需要加载
  → if (content.contains("加载中...")) → true
  → fetchChapterContent(chapterIndex)  ← 触发网络请求
  ↓
hasRestoredFromLocal = true  ← 设置标志
  ↓
网络请求返回
  → chapterContents.set(chapterIndex, realContent)
  → if (currentChapterIndex == chapterIndex) → true
  → renderChapterContent(...)  ← 应该重新渲染
  ↓
但是！用户看到的是：
  - 页面仍然显示"【正在加载章节内容...】"
  - 或者完全空白
```

### 核心问题

**问题1：loadNearbyCachedChapters 存储内容时添加了标题**

```java
// ❌ 错误代码
chapterContents.add(title + "\n\n" + (content != null ? content : "加载中..."));
```

这与之前修复"章节标题重复显示"时的原则冲突：
- 之前修改：只存储纯内容，由 reader.html 统一添加标题
- 这里又加回了标题
- 结果：标题显示两次

**问题2：没有有效内容时的处理不当**

```java
// 原始逻辑
if (content == null || content.contains("加载中...") || content.length() < 50) {
    fetchChapterContent(chapterIndex);
}
```

如果 `content = "第5章\n\n加载中..."`：
- `contains("加载中...")` → true
- 触发网络请求
- 但在等待期间，页面显示的是带标题的占位符
- 用户体验差

**问题3：网络请求返回后的重新渲染可能未执行**

虽然代码中有：
```java
if (currentChapterIndex == chapterIndex) {
    renderChapterContent(...);
}
```

但如果时序有问题，或者 `currentChapterIndex` 被其他操作改变，可能不会重新渲染。

**修改前**：

**修改后**：
```java
private boolean loadNearbyCachedChapters(long bookId, int centerChapter, int range) {
    // ...
    for (int i = centerChapter - range; i <= centerChapter + range; i++) {
        // ...
        if (title != null) {
            Chapter ch = new Chapter();
            // ...
            chapterList.add(ch);
```

**关键改进**：

- 如果内容为null，使用空字符串而不是"加载中..."
- 与之前的修复保持一致

### 2. 优化 restoreFromLocalCacheImmediately - 区分有无缓存

**位置**：ReadActivity.java 第409-448行

**修改前**：

**修改后**：
```java
private void restoreFromLocalCacheImmediately(int chapterIndex) {
    // ...
    String title = chapterList.get(chapterIndex).getTitle();
    String content = chapterContents.get(chapterIndex);
    
    // ✅ 检查内容是否有效
    boolean hasValidContent = content != null && !content.isEmpty() && 
                             !content.contains("加载中...") && content.length() >= 50;
    
    if (hasValidContent) {
        // 有缓存内容，直接渲染
        renderChapterContent(chapterIndex, title, content);
        currentChapterIndex = chapterIndex;
        
        // 延迟跳转到保存的页码（等待 WebView 分页完成）
        mainHandler.postDelayed(() -> {
            if (totalPagesInChapter > 0 && savedPage <= totalPagesInChapter) {
                webView.evaluateJavascript("jumpToPage(" + savedPage + ")", null);
            }
        }, 300);
    } else {
        // 没有有效内容，显示加载提示并触发网络请求
        Log.d("ReadActivity", "No valid cache, fetching from network: chapter " + chapterIndex);
        renderChapterContent(chapterIndex, title, "【正在加载章节内容...】");
        currentChapterIndex = chapterIndex;
        fetchChapterContent(chapterIndex);
    }
    // ...
}
```

**关键改进**：
1. **明确区分两种情况**：
   - 有有效缓存：直接渲染，跳转页码
   - 无有效缓存：显示友好提示，触发网络请求

2. **友好的加载提示**：
   - 使用"【正在加载章节内容...】"而不是空白的"加载中..."
   - 让用户知道正在加载

3. **添加调试日志**：
   - 记录何时触发网络请求
   - 方便排查问题

## 技术细节

### 1. 为什么只存储纯内容？

**原因**：
- reader.html 的 `paginate(text, title)` 函数会根据 title 参数添加标题
- 如果 content 中已经包含标题，会导致重复
- 统一由渲染层处理标题，保持数据纯净

**优势**：
- 避免标题重复
- 数据结构清晰
- 易于维护和扩展

### 2. 为什么区分有无缓存？

**原因**：
- 有缓存：立即显示，用户体验好
- 无缓存：显示友好提示，避免空白页面
- 不同的处理方式提升用户体验

**优势**：
- 用户知道发生了什么
- 不会误以为应用出错
- 加载过程更平滑

### 3. hasRestoredFromLocal 标志的作用

```java
private boolean hasRestoredFromLocal = false;

// 在 restoreFromLocalCacheImmediately 结束时设置
hasRestoredFromLocal = true;
```

**作用**：
- 防止重复恢复位置
- 确保只执行一次恢复逻辑
- 避免多次网络请求

**注意**：
- 一旦设置为 true，就不会再调用 `restoreReadingPosition`
- 所以必须在第一次就正确处理

### 4. 网络请求返回后的重新渲染

```java
if (currentChapterIndex == chapterIndex) {
    renderChapterContent(chapterIndex, chapterList.get(chapterIndex).getTitle(), realContent);
}
```

**为什么需要这个检查？**
- 用户可能在等待期间切换了章节
- 只重新渲染当前正在阅读的章节
- 避免不必要的渲染

**如果条件不满足怎么办？**
- 下次用户切换到该章节时会加载最新内容
- 或者可以添加一个"刷新"按钮

## 注意事项

1. **缓存策略**：当前缓存周围15章，可以根据需要调整范围
2. **超时处理**：如果网络请求超时，应该显示错误提示
3. **离线模式**：如果没有网络，应该显示友好的离线提示
4. **内存管理**：大量章节缓存可能占用较多内存，需要考虑清理策略
