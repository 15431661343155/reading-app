# 字体大小加载不一致问题 - 修复说明

## 问题描述

书籍样式容易加载错误，具体表现为：
1. 设置字体大小为20
2. 退出重进后，字体有时变为14（默认计算值）
3. 但UI设置面板仍显示20
4. 再次退出重进，有几率将字体大小变回20

**现象**：字体大小显示不稳定，存在竞态条件

## 问题根源分析

### 原始代码流程

```
启动 ReadActivity
  ↓
第125行: currentFontSize = getIntent().getFloatExtra("fontSize", 28f)
         → 由于没有传递fontSize参数，使用默认值28f
  ↓
第131行: loadReadingPreferencesNoApply()
         → 从 SharedPreferences 加载实际保存的值（如20f）
         → currentFontSize = 20f ✅
  ↓
第181行: webView.loadUrl("file:///android_asset/reader.html")
         → WebView 开始加载 HTML
  ↓
第175-177行: onPageFinished()
         → isWebViewReady = true
         → reader.html 中的 fontSize 初始化为计算值（如14px）❌
  ↓
章节内容加载完成
  ↓
第571-573行: renderChapterContent()
         → 调用 loadContent(chapterIndex, title, content, ...)
         → ❌ 没有传递字体大小参数！
         → ❌ 没有调用 setFontSize()！
  ↓
结果：WebView 显示的是 reader.html 的默认计算值（14px）
      而不是 SharedPreferences 中保存的值（20px）
```

### 竞态条件

**情况1：WebView 加载快于章节渲染**
```
WebView 加载完成 → fontSize = 14px（默认计算值）
章节渲染 → loadContent() → 没有应用字体 → 显示14px ❌
```

**情况2：章节渲染时 WebView 未准备好**
```
章节渲染延迟执行 → WebView 加载完成 → fontSize = 14px
延迟渲染执行 → loadContent() → 没有应用字体 → 显示14px ❌
```

**情况3：用户之前调整过字体**
```
用户调整字体到20px → applyFontSizeChange() → setFontSize(20) → 保存
退出重进 → WebView 重新加载 → fontSize = 14px（重置）
章节渲染 → 没有应用字体 → 显示14px ❌
```

**为什么有时会显示正确？**
- 如果用户在当前会话中调整过字体，WebView 中的值是正确的
- 但如果退出重进，WebView 会重新加载，字体重置为默认值

### 核心问题

**renderChapterContent() 及相关的章节加载方法中：**
1. ❌ 没有调用 `setFontSize()` 应用 Java 层的字体大小
2. ❌ 只调用了 `loadContent()` 加载文本内容
3. ❌ 假设 WebView 会保持之前的字体设置（但实际上每次加载HTML都会重置）

## 修复方案

### 核心思路

**在每次渲染章节内容后，主动应用字体大小设置到 WebView**

### 实现步骤

#### 1. 新增 applyFontSizeToWebView() 方法

**位置**：ReadActivity.java 第594-601行

```java
/**
 * ✅ 应用字体大小到 WebView
 */
private void applyFontSizeToWebView() {
    if (isWebViewReady) {
        webView.evaluateJavascript("setFontSize(" + currentFontSize + ")", null);
    }
}
```

**功能**：
- 检查 WebView 是否就绪
- 调用 JavaScript 接口 `setFontSize()` 设置字体大小
- 使用 Java 层的 `currentFontSize` 变量（已从 SharedPreferences 加载）

## 技术细节

### 1. 为什么需要主动应用字体？

**WebView 的生命周期**：
- 每次 `loadUrl()` 都会重新加载 HTML
- HTML 中的 JavaScript 变量会重置为初始值
- 之前的 `setFontSize()` 调用效果会丢失

**解决方案**：
- 在每次渲染章节后，重新应用字体设置
- 确保 WebView 中的字体与 Java 层保持一致

### 2. 为什么选择在这个时机应用？

**renderChapterContent() 之后**：
- ✅ WebView 已经加载完成（isWebViewReady = true）
- ✅ 章节内容已经加载到 WebView
- ✅ 此时应用字体，会立即生效
- ✅ 用户看到的是正确的字体

**不在 onPageFinished() 中应用**：
- ❌ 此时章节内容还未加载
- ❌ 应用字体后会被 loadContent() 的分页逻辑覆盖
- ❌ 可能导致字体不正确

### 3. 性能影响

**每次渲染调用两次 evaluateJavascript**：
```java
applyHeaderFooterSettings();  // 2次 JS 调用
applyFontSizeToWebView();     // 1次 JS 调用
```

**性能评估**：
- evaluateJavascript 是异步的，不会阻塞UI
- 总共3次JS调用，耗时可忽略（<10ms）
- 对用户感知无影响

### 4. 与其他设置的协同

**统一的设置应用模式**：
```java
// 渲染章节后
applyHeaderFooterSettings();  // 页眉页脚
applyFontSizeToWebView();     // 字体大小
// 未来可以添加更多设置应用
// applyTextColorToWebView();  // 文字颜色
// applyLineHeightToWebView(); // 行高
```

**优势**：
- 代码结构清晰
- 易于维护和扩展
- 所有设置在同一个时机应用

## 注意事项

1. **WebView 就绪检查**：所有 JS 调用前都检查 `isWebViewReady`
2. **异步执行**：evaluateJavascript 是异步的，不保证立即生效
3. **顺序重要**：先 loadContent，再应用设置，确保设置覆盖默认值
4. **一致性**：三个章节加载方法都应用相同的设置逻辑

## 可能的优化方向

### 1. 批量应用设置

将所有设置合并为一个 JS 调用：
```javascript
function applyAllSettings(fontSize, showHeaderFooter, headerFooterFontSize) {
    setFontSize(fontSize);
    setShowHeaderFooter(showHeaderFooter);
    setHeaderFooterFontSize(headerFooterFontSize);
}
```

**优势**：减少 JS 调用次数
**劣势**：耦合度增加，不够灵活

### 2. 缓存设置状态

在 reader.html 中缓存设置，避免重复应用：
```javascript
var cachedFontSize = -1;
function setFontSize(size) {
    if (size === cachedFontSize) return; // 跳过相同值
    cachedFontSize = size;
    // ... 应用字体
}
```

**优势**：避免重复操作
**劣势**：增加复杂度，收益有限

### 3. 使用 CSS 变量

通过 CSS 变量管理样式：
```javascript
document.documentElement.style.setProperty('--font-size', size + 'px');
```

**优势**：更符合现代Web标准
**劣势**：需要重构 reader.html 的样式系统
